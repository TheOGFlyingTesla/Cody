# Adoption evidence and feedback

Cody does not include telemetry. Adoption evidence must come from public GitHub
facts or information a user deliberately chooses to share.

## Acceptable evidence

- Date-stamped GitHub stars, forks, release downloads, issues, pull requests,
  and contributor activity read from the public repository.
- Opt-in installation reports submitted through the repository issue template.
- Testimonials published only with the contributor's explicit permission,
  agreed wording, attribution preference, and approved publication context.

Never infer installations from unrelated traffic, publish private support
messages, or count automated activity as a person. Do not collect repository
paths, machine names, credentials, customer data, private project content, or
ChatGPT consultation transcripts.

## Honest baseline

At the v0.1.0 launch, Cody has no claimed mobile/cloud pilot, testimonials, or
external installation count. A future pilot may test Cody against a mobile or
cloud-hosted project only after a participant opts in and the tested platform,
scope, date, commands, and limitations can be reported without private data.

Application or release notes should cite the observation date and source for
every metric. A missing metric remains “not yet collected,” never zero unless
the public source proves zero.
